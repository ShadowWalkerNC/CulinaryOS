# 🔌 MCP Microservices Architecture Spec

This document specifies the Model Context Protocol (MCP) integration for CulinaryOS. By modeling kitchen modules as standalone, local-first MCP servers, the platform guarantees ultra-low latency, strict modularity, and seamless AI agent tool invocation.

---

## 🧭 System Concepts & Protocol Design

The Model Context Protocol establishes a standard JSON-RPC 2.0 communication format between **Clients** (e.g., the CulinaryOS desktop wrapper, Compose client, or an LLM assistant) and **Servers** (our microservices).

```
┌───────────────┐                  JSON-RPC over STDIO                  ┌──────────────────┐
│               │ ───>  {"method": "tools/call", "params": ...}  ───> │                  │
│  MCP Client   │                                                       │    MCP Server    │
│ (CulinaryOS)  │ <───  {"result": {"content": [...]}}           <─── │ (KDS, POS, etc.) │
└───────────────┘                                                       └──────────────────┘
```

### 1. Transport Mechanisms
* **Local Development / Desktop App:** STDIN/STDOUT (STDIO) transport.
* **Remote / SaaS Web Deployments:** Server-Sent Events (SSE) HTTP transport.

## 🛠️ Microservice Server Definitions

### 1. POS MCP Server
Responsible for managing shopping carts, processing payments (via local Stripe emulator caches), and submitting tickets.

#### Tools Exposed:
* **`create_order`**
  * Description: Submits a new POS transaction and publishes it to the kitchen display.
  * Inputs:
    * `tableNumber` (string, optional)
    * `items` (array of objects: `productName`, `quantity`, `price`)
  * Output: Returns the generated ticket object including autogenerated UUIDs.
* **`apply_loyalty_points`**
  * Description: Deducts or appends points to a CRM loyalty account.
  * Inputs:
    * `customerId` (string)
    * `pointsToAdjust` (integer)

---

### 2. KDS MCP Server
Handles the active kitchen order queue, priorities, and bump states.

#### Tools Exposed:
* **`fetch_kds_tickets`**
  * Description: Returns the list of all active (non-bumped) tickets.
  * Inputs: None.
  * Output: List of active `KDSTicket` arrays.
* **`bump_kds_ticket`**
  * Description: Flags a ticket as complete (`status = "bumped"`), archiving it.
  * Inputs:
    * `ticketId` (string)

---

### 3. Inventory MCP Server
Tracks pantry physical counts, calculates variances, and logs material waste.

#### Tools Exposed:
* **`get_inventory_levels`**
  * Description: Queries the current stock quantities and par values.
  * Inputs: None.
* **`log_audit_count`**
  * Description: Submits a physical audit count, calculating the variance and financial loss.
  * Inputs:
    * `itemId` (string)
    * `physicalQty` (number)

## ✉️ JSON-RPC Protocol Envelopes (Examples)

### Tool Call Example: `bump_kds_ticket`
When a cook bumps a completed ticket, the client sends:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "bump_kds_ticket",
    "arguments": {
      "ticketId": "t-101"
    }
  }
}
```

And the KDS Server responds:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "Success: Ticket t-101 has been bumped and archived."
      }
    ],
    "isError": false
  }
}
```

## 💻 Client Coordination (MCPClient)

The main CulinaryOS application wraps this protocol in a client-side manager class `MCPClient` located at `web/src/services/mcpClient.ts`. 

### Key Client-side Methods:
1. **`connect(serverName, endpointUrl)`**: Subscribes to the specific server transport.
2. **`callTool(serverName, toolName, arguments)`**: Packs the payload in a JSON-RPC 2.0 structure, logs outgoing/incoming traffic to the browser console, and dispatches to the server.

### Local Mock Fallback:
For testing, the client includes an offline transport simulator. If the native servers are not active, the client falls back to processing requests locally, logging the raw JSON-RPC traffic. This allows out-of-the-box browser demonstration and validation of protocol interfaces.
