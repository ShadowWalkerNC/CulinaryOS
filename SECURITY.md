# CulinaryOS security policy
Preserve tenant isolation, server-derived authorization, integer-cent accounting, payment idempotency and signature verification. Never acknowledge uncertain settlement as paid or expose server secrets. The legacy [docs/security.md](docs/security.md) contains superseded implementation claims; use [docs/ARCHITECTURE_RESILIENCE_PLAN.md](docs/ARCHITECTURE_RESILIENCE_PLAN.md) and [docs/AI_SHARED_LEDGER.md](docs/AI_SHARED_LEDGER.md) for the current transition constraints. Do not treat service-role access as enforcing RLS or demo/health responses as isolation evidence.

Report suspected vulnerabilities privately to ShadowWalkerNC through an established private owner channel. Do not post credentials, resident/customer data or exploit payloads in public issues. Keep secrets outside Git. Production, secret, access-control and destructive changes require explicit owner approval and recovery planning. This policy describes required boundaries; it does not certify their implementation.
